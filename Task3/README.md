# AdScale: задание 3

Стратегия хранения данных, масштабирования и восстановления AdScale.


## Основное решение

У каждого сервиса есть собственные данные. Кампании, финансы и учёт оплачиваемых событий используют отдельные PostgreSQL. Аналитика работает в ClickHouse. Сервис ставок читает локальные копии кампаний и выделенных лимитов, которые обновляются через Kafka и Redis.

Сначала вводятся резервные узлы, кеш и отдельная обработка событий. Шардирование добавляется там, где измерения показывают нехватку мощности. Цели остаются прежними: 18 000 запросов/с через три месяца, 50 000 через год, доступность 99,9%. Требование нового партнёра до 80 мс сохраняется.
