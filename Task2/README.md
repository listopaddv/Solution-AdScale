# AdScale: задание 2. Проектирование RTB и интеграции с DSP

## Основное решение

Выделить сервис ставок из монолита. Принимать запросы партнёра через отдельный шлюз RTB, рассчитывать ставку по данным в памяти, а показы и клики передавать через Kafka. Управление кампаниями и финансовые операции не должны задерживать ответ на ставку.

| Связь | Выбранный способ |
|---|---|
| DSP -> шлюз RTB | HTTPS / OpenRTB 2.6 / JSON |
| Шлюз RTB -> сервис ставок | gRPC / Protobuf |
| Кабинет -> сервис кампаний | REST / JSON через шлюз управления |
| События и обновления данных | Kafka |
| Подготовленные кампании и лимиты | Redis и локальная память сервиса ставок |

## Цели и границы

Через три месяца нужны не менее 18 000 запросов/с, общий P95 не более 100 мс и ответ новому партнёру не более 80 мс. Через год сохраняются цели 50 000 запросов/с, доступность 99,9% и работа в нескольких регионах.
